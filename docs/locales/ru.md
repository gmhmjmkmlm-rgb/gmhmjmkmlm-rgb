# Привет, я Саймон 👋

Я занимаюсь разработкой низкоуровневого системного ПО с ультранизкими задержками, распределенных подсистем хранения данных и сетевых примитивов высокой производительности. Моя работа сосредоточена на стыке интерфейсов ядра Linux, неблокирующей синхронизации (lock-free concurrency) и учета архитектурных особенностей аппаратного обеспечения (Mechanical Sympathy). Когда я не занят оптимизацией структур памяти или профилированием сетевых очередей с помощью eBPF, я собираю схемы аналоговых синтезаторов и эргономичные механические клавиатуры.

- 🔭 **Текущий фокус**: Проектирование слоя асинхронной репликации с нулевым копированием (zero-copy) для распределенных журналов событий (append-only event stores).
- ⚡ **Инженерный принцип**: Предсказуемая задержка на 99-м процентиле (p99) важнее пиковой пропускной способности. Всегда измеряйте аппаратными счетчиками PMU перед тем, как строить гипотезы.
- 💬 **Темы для обсуждения**: Rust, Zig, системное программирование под Linux, структуры LSM-tree, DPDK, eBPF-телеметрия и цифровая обработка сигналов (DSP).

## 🚀 Избранные Open Source проекты

Некоторые ключевые инфраструктурные проекты, которые я спроектировал и продолжаю поддерживать:

### 1. `vortex-kv`
> Высокопроизводительный встраиваемый key-value движок хранения на языке Rust.
- **Архитектура**: Журналируемое дерево со слиянием (LSM-Tree) с прямой записью через интерфейс `io_uring` Direct I/O.
- **Особенности**: Ноль выделений памяти в куче при попадании в кэш чтения, каскадные фильтры Блума и параллельное уплотнение (compaction).
- **Производительность**: Выдерживает более 420 000 случайных операций записи в секунду на NVMe-дисках с детерминированной p99 задержкой менее одной миллисекунды.

### 2. `meshpipe`
> Модульный мультиплексор пакетов UDP/QUIC и зонд телеметрии с низкими накладными расходами на языке Zig.
- **Архитектура**: Событийно-ориентированный пул обработчиков на базе арена-аллокаторов и кольцевых буферов с выравниванием по строкам кэша.
- **Особенности**: Фильтрация пакетов на уровне ядра через eBPF XDP hook и расчет контрольных сумм с использованием векторных инструкций SIMD в пользовательском пространстве.
- **Сценарий**: Синхронизация распределенного состояния в реальном времени между узлами кластера в нестабильных сетях с потерями пакетов.

### 3. `chronos-probe`
> Легковесный демон мониторинга ядра Linux на Go и C (eBPF).
- **Архитектура**: Подключение к точкам трассировки (tracepoints) и kprobes блочного уровня дисков и сетевого стека TCP без перекомпиляции приложений.
- **Особенности**: Формирование гистограмм Prometheus без накладных расходов для анализа задержек подкачки страниц (page fault) и очередей планировщика.
- **Сценарий**: Выявление первопричин спонтанных всплесков хвостовой задержки (Tail Latency) в критически важных микросервисах.

### 4. `poly-dsp`
> Компактный синтезатор полифонических волновых таблиц на современном C.
- **Архитектура**: Неблокирующий аудиокольцевой буфер, SSE/AVX2 векторизованные осцилляторы и метод BLEP для подавления алиасинга.
- **Особенности**: Воспроизведение звука в реальном времени с параметрами 96 кГц / 32-бит float при нагрузке менее 1.2% одного ядра CPU на архитектуре x86_64.

## 📊 Архитектурная модель систем

```
 [ Клиентский уровень ]
        │  (QUIC / Бинарный протокол)
        ▼
 [ eBPF XDP фильтр ] ─── (Ранний сброс / Быстрый путь)
        │
        ▼ (Очередь завершения io_uring ядра Linux)
 [ Кольцевой буфер / SPSC очереди ] ── Выравнивание по кэш-линии
        │
   ┌────┴──────────────────────────┐
   ▼                               ▼
[ Арена памяти / Вне кучи ]     [ Дисковая надежность WAL ]
   │ (SIMD-сканирование индексов)  │ (Direct I/O O_DIRECT)
   └───────────────┬───────────────┘
                   ▼
         [ Запросы к состоянию ]
```

- **Mechanical Sympathy**: Предпочтение макета Structure-of-Arrays (SoA) перед Array-of-Structures (AoS) для максимального попадания данных в кэш L1/L2.
- **Дисциплина аллокаций**: Использование арен памяти и заранее выделенных кольцевых буферов в горячих циклах полностью исключает паузы сборщика мусора.
- **Отказоустойчивость**: Явная обработка ошибок, предсказуемое восстановление после сбоев по журналу предзаписи (WAL) и строгое тестирование на основе свойств (Property-based testing).
